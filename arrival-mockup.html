Two ways in, drawn as two

The current figure puts the adapter in the common path, which reads as though every transfer touches Ethereum. It does not. This splits the entry in two and gives each chain its own OFT, matching the architecture in the engineering diagram, in the existing style.

Proposed
Corrected against the technical diagram. My first version put a single “LayerZero OFT” box in the middle that both paths passed through. That invented a hub. The USDT0 docs are explicit: Ethereum runs OAdapterUpgradeable and every other chain runs its own OUpgradeable, so the OFT is per chain and the message travels contract to contract. LayerZero is now the arrow, not a node — which is what it is.

Reverse is real. The docs describe it directly: going back, the OFT “burns tokens on Chain A” and “a message instructs the USDT0 Adapter to unlock tokens on Ethereum.” So Stellar can send to another chain, which mints, or back to Ethereum, which unlocks. The return line says that rather than implying a symmetric round trip.

Still to decide. The numbered flows in the engineering diagram are one journey — Ethereum to B, B to A, A back to Ethereum. This figure shows arrival on Stellar instead, which is the page’s subject. If you would rather mirror their numbering, that is a different diagram, not a tweak to this one.
